# flashcards-obsidian 插件语法完整参考（v2.0.1）

来源：https://github.com/reuseman/flashcards-obsidian （当前已升级到 v2，本文件按 v2.0.1 源码与官方文档核对）

这是权威语法表，写卡片时严格照此格式，不要凭记忆改写，格式错一个字符插件就识别不出来。

> ⚠️ **v2 与 v1 的关键差异（升级后必读）**：
> 1. **ID 标记从 `^13位数字` 变成了 `^q-xxxx`**（如 `^q-tjvt`），且由插件写在前置的 ID 位置；v1 的 `^13位数字` 是历史残留，新同步不会再生成。
> 2. **`#card` 答案的跨段收集规则变了**（这是最容易误判的一条，按源码核对）：`问题 #card` 后跟列表是否被采纳，取决于 **marker 后面同一段落里有没有内容**——若 `#card` 在行尾、marker 后无内容（下一行直接就是列表/段落块），v2 **取下一个顶层节点，整个列表都是答案**（合法）；若 marker 后同一段还有文字（如 `问题 #card` 换行后又写了一句答案、再接列表），答案只取同段内容、**列表被甩出**（截断、卡片裂开）。判据：`#card` 所在行的行尾不能有别的文字，且紧邻的下一行直接是列表。拿不准就用 fenced 块（见下文）。
> 3. `#card-spaced`/`#card/spaced` 不再解析，v2 改用 `#card-reminder`。
> 4. 来源标注（Source 字段）v2 默认开启，无需手动配置。

## 前提

Anki 桌面版必须开着，且装了 AnkiConnect 插件（本 skill 只负责把卡片写进中间文件，不直接操作 Anki——同步这一步由用户在 Obsidian 里手动执行）。

## 卡片写法

### 1. 标签式 `#card`（单段答案 / 行尾 #card + 直接列表）

**先判"marker 后同段有没有内容"**（v2 源码核对过的规则）：

- `#card` 写在问题行行尾、marker 后面同一段没有别的文字 → v2 取**下一个顶层节点**：下一行直接是列表，整个列表都是答案（合法，文件里大量卡片都是这种写法）
- `#card` 行尾同一段还有内容 → 答案只取同段内容

```markdown
主一和逐物的分界到底在哪？ #card
**不在做什么，在谁做主**：我自己决定今晚就躺着刷两小时，被算法牵着就是逐物。
```

```markdown
主一和逐物的分界到底在哪？ #card
- **主一**：我自己决定"今晚就躺着刷两小时"
- **逐物**：被算法一条条牵着、回过神已经两点了
```

- **⚠️ 真正的坑是"marker 后有同段内容 + 再接列表"**：下面这种 v1 时代的写法在 v2 下会解析出"只有同段那句"的截断答案，列表内容全部丢失、卡片裂开：
  ```markdown
  ❌ 错误（v1 兼容写法，v2 已不认）：
  问题 #card
  答案第一行
  - 列表项1
  - 列表项2
  ```
  列表被甩出，是因为 `#card` 后面同一段已经有了"答案第一行"。**想用列表答案就保证 `#card` 在行尾、紧邻下一行直接是列表**；拿不准或答案既要引导句又要列表，用 **fenced 块**（下一节）。
- 反转卡（正反面各生成一张）：把 `#card` 换成 `#card-reverse`，或用 Obsidian 层级标签写法 `#card/reverse`
- 提醒卡（只做单向定期复习，不建正反对子）：`#card-reminder`（v2 已不再支持 v1 的 `#card-spaced`/`#card/spaced`）：
  ```markdown
  这是一句想要定期回顾的话 #card-reminder
  ```

### 2. fenced 块 ` ```flashcard `（多行/列表答案——v2 推荐）

答案需要多行、列表、多段落结构时，用代码块形式（`front:`/`back:` 必填，值可以跨多行，空行保留）：

````markdown
```flashcard
front: 主一和逐物的分界到底在哪？
back: **不在做什么，在谁做主**：
- **主一**：我自己决定"今晚就躺着刷两小时"
- **逐物**：被算法一条条牵着、回过神已经两点了
```
````

- `type: reversed` 生成反转卡（默认 basic）；`type: reminder` + `content:` 是提醒卡
- **注意**：答案行里如果有一行恰好以 `front:`/`back:`/`content:`/`type:` 开头，会被当成新字段而不是答案内容——遇到这种行要改写措辞
- fenced 块的 context 与普通卡一致（取其所在 `## 单元N` 标题），正片不会受代码块样式影响

### 3. 独立 `#card` 行 + 纯列表（多行答案的另一种写法）

`#card` 单独占一行，紧跟问题的下一行；答案取**紧跟在它后面的下一个节点**（整个列表也可以）：

```markdown
主一和逐物的分界到底在哪？
#card
- **主一**：我自己决定"今晚就躺着刷两小时"
- **逐物**：被算法一条条牵着、回过神已经两点了
```

- 局限：答案只能取**一个**节点（一个列表或一个段落）。如果答案既有引导句又有列表，把引导句并成列表第一项，或改用 fenced 块
- 不要用它写"答案第一行 + 空行 + 更多"，空行会切断

### 4. 行内格式 `问题::答案`（最省事，适合一句话问答）

**必须写在同一行**，冒号两边空格随意：

```markdown
我的问题::我的答案
我的问题:: 我的答案
我的问题 ::我的答案

- 列表里也能用:: 我的答案
```

反转（生成正反两张卡）用三个冒号 `:::`：

```markdown
我的问题:::我的答案
```

**限制**：这种格式答案不能换行、不能带多段落结构——需要多行答案时改用 fenced 块或 `#card`。

### 5. Cloze 挖空

三种写法：

```markdown
这是一个 ==挖空的词== 示例
这是一个 {1:挖空的词} 示例
这是一个 {{c1::挖空的词}} 示例（Anki 原生格式，v2 支持，但没必要用）
```

**⚠️ 编号规则（v2 最容易踩的坑）**：

- `==text==`（自动 cloze）：**每个标记自增编号**——第一个 `==词==` 是 c1、第二个是 c2、第三个是 c3……**各自生成一张独立卡**
- `{N:text}`（数字 cloze）：按写的编号。**复用同一编号**（如 `{1:a}` `{1:b}`）就把多个空绑在同一张卡上，复习时一张卡同时挖出所有同编号空
- `{{cN::text}}`（原生）：v2 支持，但 Obsidian 里显示难看，不要主动写

**⚠️ 多空必须复用编号**：一句话想挖两个以上词（金句卡常见），写 `{1:词}` `{1:词}` 绑成一张卡。**不要用 `==词==` 写多空**——自增编号会把它们拆成多张独立卡，而且 **Anki 不会为新增编号自动补卡**：AnkiConnect 更新既有卡片只改内容、不重建卡片，症状就是"第二个空没生成"——卡面上那个词直接显示成明文，像从没挖过一样。这是 v1 时代"多空全用 `==词==`"的写法在 v2 下真实踩出的坑（"良知是天生的种子，不是天生的果实"那张卡）。**单空继续用 `==词==`**——不会像 `{}` 那样让 Obsidian 笔记正文看起来奇怪。

**⚠️ 不要跟行内 `::`/`:::` 混用在同一行**：`::`/`:::` 是行内问答卡的分隔符，cloze 是完全独立的第三种卡片机制，两者不能共存在同一行。比如 `问题::「原文……==挖空词==……」` 这种写法，插件会同时按"行内问答"和"cloze"两套逻辑各自生成一张卡，实际效果是同一行长出两张互相打架的卡（Anki 里表现为该行对应出现两个 `^id` 标记）。**一行只能选一种**：想要 cloze 挖空，就把整行写成不带 `::` 的纯段落（问题背景可以作为 cloze 段落前半句的说明文字，跟原文写在同一段里）；想要行内问答，答案就不能包含 `==...==`/`{}` 挖空标记，改用普通文字。

**⚠️ cloze 卡的匹配范围是"物理行"，不是整个段落**：只要遇到一个真正的换行符，当前 cloze 卡就必然在那里结束，接下来的内容会被当成**下一张独立的卡**去解析，哪怕两行写了相同的编号（如两行都写 `{1:...}`），它们也不会因为编号相同就合并成一张卡。**如果确实需要几行内容绑成一张卡一起挖空**（比如古诗的上下两句要连着测），唯一办法是把这几行写在同一个物理行里，行间用 `<br>` 代替真正的换行符——`<br>` 不是换行符，不会打断匹配，同时 Anki 渲染时又会正常显示为换行。真正的换行符只能留给"这两部分本来就该是独立卡片"的场景。

### 6. 目标卡组 / 标签（写在文件顶部 frontmatter）

```yaml
---
cards-deck: 卡组名
tags: 全局标签1, 全局标签2
---
```

- 子卡组用双冒号：`cards-deck: XX学习域::单元1`
- 局部标签（只给某一张卡加）：写在 `#card` 标签后面，如 `问题 #card #重点`

## Context-aware 模式（默认开启，写卡片时必须意识到）

卡片正面会自动拼上**从顶层标题到这张卡所在标题的完整路径**，作为唯一化的上下文。比如文件结构是：

```markdown
## 单元1 · 核心命题
某思想家的"核心命题"是什么？ #card
```

生成到 Anki 里的正面实际是：`单元1 · 核心命题 > 某思想家的"核心命题"是什么？`

**这意味着**：
- 不同单元下即使问法完全一样也不会冲突，不用刻意在每个问题里重复"单元几"这种前缀
- 但也因此，**卡片一定要挂在正确的 `##`/`###` 结构标题下面**（比如上面的 `## 单元1 · 核心命题`），孤零零丢在文件顶层会导致上下文缺失、正面显得很秃

**⚠️ 踩过的坑（v2 同样存在）**：context 只认文件里真实的 markdown 标题（`#`/`##`/`###` 开头的行）。如果某张卡片的问题本身是用 `### 问题 #card` 这种标题写法写的，它就会变成文档结构里一个真正的三级标题。后果是：**紧跟在它后面、且中间没有再出现新标题的所有卡片**在计算自己的祖先路径时，会把这张"标题卡"的问题也当成祖先标题拼进去，导致正面越叠越长，甚至出现"卡片A的问题 > 卡片B的问题"这种不该有的嵌套。**规避方法只有一个**：单张卡片的问题永远写成独立一行的纯段落文字，不加任何 `#` 前缀；`#`/`##`/`###` 只用在真正划分笔记结构的地方（比如按单元分组的 `## 单元N`），不要用在单张卡片自己的问题上。

## 增量更新的追踪机制（v2）

1. 在 Obsidian 里对文件执行 `Ctrl+P → Flashcards: generate for the current file`，插件会给每张卡插入一行形如 `^q-tjvt` 的 ID 标记（v2 是 `q-` 开头的 4 位随机串；v1 遗留的 `^13位数字` 是旧 ID，迁移到 v2 后新同步会以 `^q-xxxx` 为准）
2. **这个标记是插件用来对应"这张卡是 Anki 里的哪张卡"的，人工编辑时绝对不能删**，删了插件会当成新卡重复插入
3. 以后要改内容：改 ID 标记上方的文字（fenced 卡就改 `front:`/`back:` 里的内容），重新跑一次生成命令，插件识别到 ID 相同就做**更新**，不会重复建卡
4. 要删除某张卡：把卡片正文内容删空，但保留那行 ID 标记不动，插件会据此在 Anki 里同步删除
5. **同步时 Anki 的 Browse 窗口必须关着**，插件用的 API 在 Browse 开着时会更新失败（这是插件已知的限制，不是操作失误）

## 其它支持（用得上再展开，平时不用管）

- **LaTeX**：`$3+4$` 或 `$$50+2$$`，Obsidian 原生语法直接写
- **代码高亮**：Obsidian 的代码块语法直接支持
- **图片**：用 Obsidian 的 embed 语法 `![[图片.png]]` 正常嵌入即可
- **来源标注（source）**：v2 默认开启，卡片会自动带上指向 Obsidian 源文件的"Edit source"链接，无需手动配置
