# flashcards-obsidian 插件语法完整参考

来源：https://github.com/reuseman/flashcards-obsidian/wiki

这是权威语法表，写卡片时严格照此格式，不要凭记忆改写，格式错一个字符插件就识别不出来。

## 前提

Anki 桌面版必须开着，且装了 AnkiConnect 插件（本 skill 只负责把卡片写进中间文件，不直接操作 Anki——同步这一步由用户在 Obsidian 里手动执行）。

## 四种卡片写法

### 1. 标签式（标题或整行 + `#card`）

标题（或独立一行文字）后面打 `#card`，下一行紧跟着写背面，**中间不能空行**；卡片与卡片之间用**空行**隔开：

```markdown
## 这是问题 #card
这是答案。

这一行不会被算进卡片，因为上面隔了一个空行。
```

- 反转卡（正反面各生成一张）：把 `#card` 换成 `#card-reverse`，或用 Obsidian 层级标签写法 `#card/reverse`
- 间隔卡（只做单向定期复习，不建正反对子）：`#card-spaced` 或 `#card/spaced`，直接写在要记的那句话末尾，不需要单独的答案行：
  ```markdown
  这是一句想要定期回顾的话 #card-spaced
  ```

标题不是必须的，独立一行文字打 `#card` 也生效：
```markdown
这是问题
#card
这样写可以避免在 Obsidian 里到处出现 #card 标签的视觉干扰
```

**⚠️ 单张卡片的问题不要用 `#`/`##`/`###` markdown 标题写法**（即上面第一个例子里 `## 这是问题 #card` 这种形式），**一律用"独立一行文字 + #card"**。原因见下面 context-aware 一节——用标题写法会让它变成文档结构里真正的标题，污染后面卡片的上下文。`#`/`##`/`###` 只保留给整理笔记结构用的真实分区标题（比如按单元分组的 `## 单元N`），不要挂在单张卡片的问题上。

### 2. 行内格式 `问题::答案`（最省事，适合一句话问答）

**必须写在同一行**，冒号两边空格随意，以下写法都认：

```markdown
我的问题::我的答案
我的问题:: 我的答案
我的问题 ::我的答案

- 列表里也能用:: 我的答案
```

反转（生成正反两张卡）用三个冒号 `:::`：

```markdown
我的问题:::我的答案
```

**限制**：这种格式答案不能换行、不能带多段落结构——需要多行答案时改用标签式 `#card`。

### 3. Cloze 挖空

两种写法效果一样，任选：

```markdown
这是一个 ==挖空的词== 示例
这是一个 {挖空的词} 示例
这是一个 {2:第二个挖空} 示例（数字指定挖空顺序，一句话里有多个空时用）
```

优先用 `==高亮==` 写法——不会像 `{}` 那样让 Obsidian 笔记正文看起来很奇怪。

**⚠️ 不要跟行内 `::`/`:::` 混用在同一行**：`::`/`:::` 是行内问答卡（第2种写法）的分隔符，cloze 是完全独立的第三种卡片机制，两者不能共存在同一行。比如 `问题::「原文……==挖空词==……」` 这种写法，插件会同时按"行内问答"和"cloze"两套逻辑各自生成一张卡，实际效果是同一行长出两张互相打架的卡（Anki 里表现为该行对应出现两个 `^id` 标记）。**一行只能选一种**：想要 cloze 挖空，就把整行写成不带 `::` 的纯段落（问题背景可以作为cloze段落前半句的说明文字，跟原文写在同一段里）；想要行内问答，答案就不能包含 `==...==`/`{}` 挖空标记，改用普通文字。

**⚠️ 也不要写成 `{{c1::文字}}` 这种形式**——这是 Anki 桌面版内部存储 cloze 卡的原始格式，不是 flashcards-obsidian 的插件语法，插件识别不出来。正确写法只有本节列出的三种：`==词==`（推荐）、`{词}`、`{2:词}`。

**⚠️ cloze 卡的匹配范围是"物理行"，不是整个段落**（查过插件源码 `regex.ts` 的 `cardsClozeWholeLine` 验证过）：这条正则没有加 dotall 标志，`.` 无法匹配真正的换行符 `\n`，而正则本身用 multiline 模式的 `$` 兜底收尾——意味着只要遇到一个真正的换行符，当前 cloze 卡就必然在那里结束，接下来的内容会被当成**下一张独立的卡**去解析，哪怕两行写了相同的编号（如两行都写 `{1:...}`），它们也不会因为编号相同就合并成一张卡——因为它们根本不是同一个 note。这跟标签式 `#card`（正则里显式允许多行 `(?:[^\n]\n?)+?`）完全不同，容易踩坑当成"cloze 也支持多行答案"。**如果确实需要几行内容绑成一张卡一起挖空**（比如古诗的上下两句要连着测），唯一办法是把这几行写在同一个物理行里，行间用 `<br>` 代替真正的换行符——`<br>` 不是换行符，不会打断正则匹配，同时 Anki 渲染时又会正常显示为换行，两全其美；真正的换行符只能留给"这两部分本来就该是独立卡片"的场景。

### 4. 目标卡组 / 标签（写在文件顶部 frontmatter）

```yaml
---
cards-deck: 卡组名
tags: 全局标签1, 全局标签2
---
```

- 子卡组用双冒号：`cards-deck: XX学习域::单元1`
- 局部标签（只给某一张卡加）：写在 `#card` 标签后面，如 `问题 #card #重点`

## Context-aware 模式（默认开启，写卡片时必须意识到）

卡片正面会自动拼上**从顶层标题到这张卡所在标题的完整路径**，作为唯一化的上下文。比如文件结构是：

```markdown
# XX学习域 Anki 卡片
## 单元1 · 核心命题
某思想家的"核心命题"是什么？ #card
```

生成到 Anki 里的正面实际是：`XX学习域 Anki 卡片 > 单元1 · 核心命题 > 某思想家的"核心命题"是什么？`

**这意味着**：
- 不同单元下即使问法完全一样也不会冲突，不用刻意在每个问题里重复"单元几"这种前缀
- 但也因此，**卡片一定要挂在正确的 `##`/`###` 结构标题下面**（比如上面例子里的 `## 单元1 · 核心命题`），孤零零丢在文件顶层会导致上下文缺失、正面显得很秃

**⚠️ 踩过的坑**：`getContext()` 的实现只认文件里真实的 markdown 标题（`#`/`##`/`###` 开头的行），不管这一行是"给笔记分区用的标题"还是"顺手用标题写法写的一张卡片"。如果某张卡片的问题本身是用 `### 问题 #card` 这种标题写法写的，它就会变成文档结构里一个真正的三级标题。后果是：**紧跟在它后面、且中间没有再出现新标题的所有卡片**（不管是行内 `::`、cloze，还是普通 `#card`）在计算自己的祖先路径时，会把这张"标题卡"的问题也当成祖先标题拼进去，导致正面越叠越长，甚至出现"卡片A的问题 > 卡片B的问题"这种不该有的嵌套。**规避方法只有一个**：单张卡片的问题永远写成独立一行的纯段落文字，不加任何 `#` 前缀；`#`/`##`/`###` 只用在真正划分笔记结构的地方（比如按单元分组的 `## 单元N`），不要用在单张卡片自己的问题上。

## 增量更新的追踪机制

1. 在 Obsidian 里对文件执行 `Ctrl+P → Flashcards: generate for the current file`，首次生成后，插件会在每张卡片后面自动插入一行形如 `^1607361487244` 的 ID 标记
2. **这个标记是插件用来对应"这张卡是 Anki 里的哪张卡"的，人工编辑时绝对不能删**，删了插件会当成新卡重复插入
3. 以后要改内容：改 ID 标记上方的文字，重新跑一次生成命令，插件识别到 ID 相同就做**更新**，不会重复建卡
4. 要删除某张卡：把卡片正文内容删空，但保留那行 ID 标记不动，插件会据此在 Anki 里同步删除
5. **同步时 Anki 的 Browse 窗口必须关着**，插件用的 API 在 Browse 开着时会更新失败（这是插件已知的限制，不是操作失误）

## 其它支持（用得上再展开，平时不用管）

- **LaTeX**：`$3+4$` 或 `$$50+2$$`，Obsidian 原生语法直接写
- **代码高亮**：Obsidian 的代码块语法直接支持
- **图片**：用 Obsidian 的 embed 语法 `![[图片.png]]` 正常嵌入即可
- **来源标注（source）**：需要在插件设置里手动开启，默认关闭，开启后旧卡无法再被更新（除非关回去），不建议中途切换
